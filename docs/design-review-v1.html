effbench · design review v1 · 17 aug 2026 · reviewed against v0.5.0

From dark mode default to instrument.

effbench measures the single most important number in local AI — effective speed, accuracy included. The product deserves a surface that treats that number like the hero it is. Today both surfaces (web UI and report) are competent dark-mode defaults: readable, inoffensive, and interchangeable with a thousand GitHub clones. This review defines what "beautiful" means for effbench in concrete, shippable terms, shows it in mockups using real run data, and sequences the work.

1 · The one idea

effbench is a precision instrument, and it should look like one. Oscilloscopes, high-end multimeters, Leica M-series: dark housing, luminous readouts, one accent, everything else recedes so the measurement is the loudest thing on the panel. That is the whole design. Consequences:

  • The numerals are the interface. Every screen is arranged so the eye lands on a number first, a label second, chrome never.
  • One accent, one glow. Mint (#4FE3C1) is the instrument light. Semantic pass/warn/fail colors appear only where a verdict exists. No second brand hue.
  • Graphite, not black-boxes. A four-step surface ramp (void → carbon → graphite → hairline) replaces today's flat card-on-card panels. Depth comes from the ramp and 1px hairlines, never from drop shadows.
  • Nothing decorative survives. If an element doesn't measure, signal state, or guide the next click, it isn't on the panel.

3 · The system

One token source, generated into both surfaces from a single Python constant so they can never drift again (the report stays a self-contained file; the UI stays stdlib-served — constraint intact).

# effbench/tokens.py — the single source of truth, interpolated into both CSS blocks TOKENS = { "void": "#07090D", # page "carbon": "#0D1117", # panels / cards "graphite": "#161C24", # raised / hover / tracks "hairline": "#1F2733", # the only border color "ink": "#E8EDF4", # primary text "ink2": "#9AA6B5", # secondary text "ink3": "#5C6875", # labels / tertiary "mint": "#4FE3C1", # THE accent — instrument light "pass": "#4ADE80", # semantics only, never chrome "warn": "#FBBF24", "fail": "#F87171", }

All OS-native stacks — zero web fonts, per the no-dependencies rule. tabular-nums everywhere a digit can change; digits stop dancing.

Motion & material rules

  • Hovers: background-color 140ms ease-out on the row/panel. Never all, never filter.
  • Panel transitions (progress appear, summary reveal): 240ms ease-out, translate up 4px + fade.
  • Per-task rows in a live run: fade in 160ms as they resolve. This is the product's heartbeat; give it a pulse.
  • The hero number gets the only glow in the product (text-shadow 0 0 24px rgba(mint, .18)). One glow. If two things glow, nothing does.
  • prefers-reduced-motion: all durations → 0ms. Non-negotiable.

5 · The plan

P0 · One palette, one type system ~a day

risk: low · touches: tokens.py (new), webui.html, report.py _css() · ships: v0.6.0
  • Create effbench/tokens.py; generate both CSS blocks from it. Delete the web UI's blue and the report's separate palette in the same commit.
  • Type ramp + tabular-nums everywhere digits change; mono for metrics/labels.
  • Hairline discipline: one border color, four-step surface ramp, no shadows.
  • Fix the iframe white flash (background: var(--void)).
  • Motion scale (140/240ms) + prefers-reduced-motion.

P0 alone moves every score column. It is pure CSS/token work; zero behavior change, zero suite contact.

P1 · The hero compositions ~2 days

risk: medium · touches: report.py, webui.html render paths · ships: v0.6.0
  • Report: instrument cluster (mockup A) replaces the stat-card row + separate verdict; verdict copy restructured conclusion-first.
  • Report: purpose ladder replaces radar (mockup B). Radar code retained for none — delete it.
  • Web UI: run summary adopts the same cluster in miniature, so the moment a run finishes, the UI and the report agree visually.
  • Task rows become metric rows (mockup C) in both surfaces.

P2 · The moments ~2 days

risk: medium · touches: webui.html JS · ships: v0.6.x
  • Live run: per-task lines resolve with a 160ms fade; the bar becomes a segmented progress rail (12 segments for quick, 36 for full) — progress you can count.
  • First-run state: a welcome composition instead of "loading…" forever; includes "no server found → here's how to start one" path (pairs with the find-servers roadmap item).
  • Compare view: dumbbell rows (mockup D) with percent deltas.
  • Print stylesheet for reports: reports print as clean paper documents (invert to white, hide chrome) — the share-to-PDF path.

P3 · The delight layer ~1 day, do last

risk: low · ships: v0.7
  • The one glow on the hero number. Accept-rate micro-strip. Eff-t/s trend sparkline across run history on the home panel.
  • Empty/error states rewritten as designed moments (no server, no runs, no reference data).

6 · What we will not do

  • No web fonts, no CDN, no JS libraries. The no-dependencies rule is a product feature, not an inconvenience. System stacks are capable; the discipline is the style.
  • No gradients, no glassmorphism, no rainbow accents. The instrument idea survives on four surfaces, one accent, and hairlines. The moment chrome starts glowing, the numbers stop being the loudest thing.
  • No decoration that doesn't measure. Every pixel in the mockups encodes a value, a state, or the path to the next action.
  • No change to suites, graders, or ledger format. This entire review is presentation-layer. Frozen things stay frozen.
  • And a note for all copy: verdicts lead with the conclusion ("Server healthy"), not the hedge. Numbers justify, they don't narrate.

7 · Getting in and out — the appliance question

The same review lens applies to the product's front door. Today: irm …/install.ps1 | iex in PowerShell, and a Python process that lives only as long as a console window. For a non-technical daily driver, the answer is a desktop shortcut, not a service:

1
Install once (technical, already solved)

The one-liner stays the install path. At the end it drops “effbench” onto the Desktop and Start Menu — a shortcut pointing at the existing launcher with a ui argument.

2
Start daily (double-click)

Shortcut opens a titled console — “effbench — close this window to stop” — starts the local server, opens the browser. Same window-alive-means-running convention your llama-server launchers already use.

3
Stop (close the window)

No background service, no tray icon, no admin rights, nothing to uninstall to be rid of. The privacy footer already says “nothing leaves your computer” — the lifecycle now behaves like it too.

4
macOS twin

Same move: a double-clickable effbench.app wrapper (a .command in disguise) in /Applications. Same start/stop semantics.

Proposal only — not implemented. It's a ~30-line addition to both installers plus launcher titles, slots naturally into v0.6 alongside the find-servers button, and touches nothing frozen.
